# Composition and craft

Use this across platforms; use the built-in web foundation for its detailed website recipes and runnable tools. The result should explain this product and support this task before it displays a fashionable visual technique.

## Resolve the composition

Write the focal subject, first reading path, primary action, supporting evidence, alignment anchors and intended density. Sketch all three candidate silhouettes with real content before selecting components. A split hero, centered statement and immersive product stage are different only if their content scale, proof placement and reading rhythm differ. Three versions of one card grid do not qualify.

| Surface | Build the visual argument around | Reject |
|---|---|---|
| Software marketing | A specific input, action and observable product result | Anonymous dashboard furniture, fake metrics and a glowing object as the only product explanation |
| Physical product | The item at useful scale, details, use and purchase facts | An abstract substitute for a missing product photograph |
| Service or place | Authentic work, people, location or delivery process | A technology-themed shader that obscures the offer |
| Web application | The next decision, useful records and actionable state | A marketing hero above every workspace or giant empty KPI cards |
| Desktop tool | Work surface, selection, contextual tools, shortcuts and persistent spatial relationships | Stretched phone screens, excess card padding and hidden essential controls |
| Mobile app | One immediate task, thumb-reachable actions, understandable navigation and readable native scale | A shrunk desktop layout or decorative device frame inside the application |

For every marketing section record `reader question | answer | proof | composition | next action`. Keep only sections with a job. Counts follow real content. Use contrasts of scale, density and image treatment within one system. Do not append a FAQ, stats strip or bento just to fill a page. For app screens, stable repeated anatomy is a strength; variation should not destabilize task learning.

## Make exact visual decisions

1. **Type:** specify roles and actual family/fallback, weight, size, line height, measure and tracking. Test the real longest heading and the final font. Use display character where appropriate and readable text for work. Align comparison numbers with tabular numerals. Do not make every technical label monospace.
2. **Space:** define page gutters and alignment lines first, then grouping gaps, component insets and row pitch. Related label/value pairs stay closer than unrelated groups. Avoid `space-between` as a substitute for deliberate internal gaps. Correct optical alignment after geometric alignment.
3. **Color:** use semantic canvas/surface/ink/muted/border/accent/focus/status roles. Derive an original palette from the target brand and content, not the source screenshot. Check adjacent pairs in all intended themes and actual material layers. Accent needs a job; status colors keep distinct meaning.
4. **Shape:** define a small hierarchy for controls, content groups, overlays and imagery. Nested radii follow the inset and silhouette. Hit area and visible glyph are separate. Never apply a large pill radius to every rectangle.
5. **Depth:** assign levels to background, work surface, raised controls and overlays. Choose border, tint or shadow for a relationship; do not pile on all three indiscriminately. Glass needs readable foreground and a useful background.
6. **Assets:** name the subject, focal crop, placement, size variants, source/rights, loading behavior and fallback before building the frame. Missing key imagery is a design dependency, not permission for arbitrary CSS blobs. Request generation permission when it would materially improve the direction.
7. **Icons:** one coherent UI family with deliberate size, stroke and optical alignment. Use authentic product logos only for truthful associations; do not invent endorsements. Label unfamiliar actions.
8. **Motion:** apply the motion contract to relationships and actual state changes. A strong settled frame must work before motion begins and when it is disabled.

Render a specimen in the actual task: populated content, long label, primary/secondary actions, focus/error, overlay and compact view where relevant. A token table without a rendered consumer is not a resolved system.

## Content that does design work

Build a fact sheet: what it is, who uses it, what they do, the real mechanism, limitations, evidence, offer and actual action destination. Use these facts to write the hierarchy. Do not manufacture testimonials, client marks, usage figures, prices, certifications or invented specificity.

Write a short voice card from the audience and existing writing. Keep domain nouns consistent. Action labels name their effect. Show price units and terms next to the choice they qualify. Errors name the recoverable action. Keep copy devices varied: repeated two-fragment headings, synthetic sincerity, ubiquitous eyebrows and endless contrast phrases can look generic even without banned buzzwords. Test whether a competitor's name could replace the product without changing anything meaningful; repair the facts and structure, not merely the adjectives.

## Diagnose and correct in order

- Thumbnail/full-page: identify the main mass, rhythm, hierarchy and product specificity. Fix these before decoration.
- Reading scale: inspect measure, line breaks, grouping, baselines, row density, panel relationships, credible data and image crop.
- Detail scale: inspect control padding, icon alignment, focus clearance, clipping, status marks, numeral units and transition endpoints.

For each defect record the visible symptom, cause, proposed correction and recheck. If a design fails when decorative effects are removed, strengthen its content and composition. If a beautiful screenshot cannot complete the task, correct the experience. Never replace actual evidence with a numerical taste score.
